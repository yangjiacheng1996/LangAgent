### 3.3 优先级链（必须严格生效）

```
CLI 参数  >  环境变量  >  智能体目录 .env  >  内置默认值
```

- CLI 参数：来自 `cli_runner.parse_argv()`。
- 环境变量：`os.environ` 快照（仅在 resolve 开始时取一次，避免运行时变更污染）。
- .env 文件：`agent_dir/.env`，用 `python-dotenv` 解析。
- 内置默认值：`langagent/runtime/defaults.py` 中硬编码（最小可用集合）。

### 3.5 阶段能力边界

- `config_resolve` 阶段**只读取**：CLI 参数 / `os.environ` / `.env` / 内置默认。
- `config_resolve` 阶段**不得实例化**：`BaseChatModel`（由 F01 model_adapt 处理）。
- `config_resolve` 阶段**不得加载目录**（由 F06 dir_load 处理；本 feature 接收 `agent_dir` 路径作为输入，不调用 F06）。
- **越权检测**：探测到实例化模型 → 抛 `StageCapabilityViolationError`，退出码 1。
- **F07 阶段级黑名单**（**review.md v1.1.0 P1-7 修复后引用 F06 §3.4** + **review.md v2.2.0 修复 P1-6 后严格对齐权威源** + **review.md v2.2.2 P0-1 修复后引用 cross_cutting_stage_guard**）：monkeypatch 黑名单 = `[BaseChatModel.__init__, RuntimeDirLoader.load, chat_model_factory.create]`；audit_event 黑名单 = `[]`（config_resolve 阶段不读文件）；阶段装饰器 `@cross_cutting_stage_guard_decorator('config_resolve', monkeypatch_blacklist=[BaseChatModel.__init__, RuntimeDirLoader.load, chat_model_factory.create])` 由 F06 `cross_cutting/stage_guard.py` 提供的跨 feature 复用工具应用（详见 F06 §3.4b + F06 §3.4{#stage-blacklist-table}）。
  > **来源注（review.md v0.1.0 R-005 修复明确）**：`stage_guard` 是 `workflow.md §"失败模式" stage_capability_violation` 的实现，**不是宪法第 V 条子条款**（宪法第 V 条仅含智能体目录契约：强制布局 / 强制性规则 / `langagent init` 命令语义，不含 6 阶段能力约束）。stage_capability_violation 概念源自 workflow.md，由 F06 §3.4 阶段级黑名单 + `@stage_guard_decorator` 实施。

## 五、关键约束

1. **优先级刚性**：CLI > env > .env > 默认；任何配置项不得反向覆盖。
2. **不读 langchain**：本 feature 不直接 import `langchain`；模型实例化在 F01。
3. **不实例化模型**：违反抛 `StageCapabilityViolationError`。
4. **frozen=True**：RuntimeConfig 一旦产出不可修改；改字段必须重建实例。
5. **脱敏日志**：密钥 / token 字段一律不打印原文；`OPENAI_API_KEY` 等即使在 env 中也不进日志。
6. **依赖方向**：runtime 不得反向依赖 cli；本模块仅依赖 F02 logger + 类型注解。
7. **TDD 刚性**：先 Red 后 Green 再 Refactor。
8. **第 XV 条对齐清单**：与宪法第 IV 条（模型抽象层 — 6 种 provider）/ 第 XII 条（配置与可观测契约 — 优先级链 + 启动日志）/ 第 XIII 条逐项对齐。
