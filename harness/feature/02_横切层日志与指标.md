## 一、Feature 概述

实现 cross_cutting 层的两个模块：
- **`cross_cutting_logger`**：以 `la.` 前缀发出结构化日志；按 `log_level` 过滤；所有阶段可见。**review.md v0.5.0 修复（评审 v0.1.0 §二.A.3 方案 A）**：本模块除日志发射外，**同时承载 `EventBusProtocol` 接口定义**（`publish` / `subscribe` / `unsubscribe` / `flush` 4 个方法），被 F03 `protocol_event_bus` 实现、被 F02 `cross_cutting_metrics_collector` 子模块消费；模块总数仍为 19。
- **`cross_cutting_metrics_collector`**：按时间窗口聚合 latency / error_rate / token_usage / cost_usd，产出 `MetricsSnapshot`。

本 feature 是 LangAgent 可观测性的基石。所有阶段、所有模块均允许调用本 feature；F02 不依赖任何业务层（cli / runtime / protocol），仅依赖 primitives 层类型注解（F01）与 F03 事件总线实现（metrics 子模块消费）。

### 关于 cross_cutting_logger 同时承载 logger + EventBusProtocol 的设计权衡（review.md v0.1.0 R-004 修复补充）

`cross_cutting_logger` 模块内同时存在两类语义不相关的接口：
- `emit(tag, payload)` / `set_level(level)` / `drain_spans()` —— 日志发射
- `class EventBusProtocol(Protocol)` —— 事件总线协议

这是 v0.5.0 §二.A.3 方案 A 修复后的**有意设计权衡**，不是疏漏：
- ✅ 两个接口都是**被动接口**（调用方主动 push，模块不反向依赖）；合并不引入分层违例。
- ✅ 维持 19 个 module_id 总数不变（避免 architecture_modules.md 模块计数变动）。
- ✅ 两者都属"横切层基础设施"（logging + messaging 都是 cross_cutting concern）。
- ⚠️ 但从**单一职责原则**看，logger 与 EventBusProtocol 概念上分属"日志基础设施"与"消息基础设施"。
- 权衡结论：保持合并；拆分代价（新增 1 个 module_id + 拆分维护）大于收益（概念清晰度）。本权衡理由在 `architecture_modules.md#mod-cross-cutting-logger` 副职责 2 同步登记。

### 关键内部相位

F02 包含的 2 个模块有内禀依赖顺序：
- **Phase 1**：`cross_cutting_logger`（无运行时依赖，单独可 TDD；含 `EventBusProtocol` 接口定义）。
- **Phase 2**：F03 完成后再回填 `cross_cutting_metrics_collector`（订阅 event bus；消费 EventBusProtocol 接口）。

**脱敏精确字段名清单**（**review.md v2.2.0 修复 P2-3**：原 prose "子串匹配"改为**精确字段名匹配**，避免误命中 `input_tokens` / `output_tokens` / `total_tokens` 等 LangChain `AIMessage.usage_metadata` 子键）：

```python
# langagent/cross_cutting/logger.py 脱敏实现
_REDACT_KEYS = frozenset({"api_key", "password", "secret", "token"})  # 精确字段名匹配（非子串）

def _redact(payload: dict[str, Any]) -> dict[str, Any]:
    """深度遍历 payload dict；任意 key 命中 _REDACT_KEYS 替换值为 '***'。"""
    out = {}
    for k, v in payload.items():
        if k in _REDACT_KEYS:                        # 精确匹配（review.md v2.2.0 P2-3 修复）
            out[k] = "***"
        elif isinstance(v, dict):
            out[k] = _redact(v)                      # 递归
        elif isinstance(v, list):
            out[k] = [_redact(x) if isinstance(x, dict) else x for x in v]
        else:
            out[k] = v
    return out
```

> **P2-3 修复对照**：原 v1.1.0 P2-3 修复 prose "payload 含 `api_key` / `password` / `secret` / `token` 字段名 → 替换为 `***`" 表述模糊。LangChain `AIMessage.usage_metadata` 字段含 `input_tokens` / `output_tokens` / `total_tokens` 子键，**子串匹配 `token` 会误命中**。本修复显式声明**精确字段名匹配**，白名单反义方案 `("input_tokens", "output_tokens", "total_tokens")` 不再需要。

### 3.4 日志输出目标（**review.md S-6 修复后**）

- **stderr**（人类可读文本 + JSONL 格式，两种格式同时输出，便于机器解析与人类阅读）：
  - 文本格式：带 ANSI 色码，可关闭；每行 `[<tag>] <message>` 形式。
  - JSONL 格式：每行一条事件，含 `tag` / `timestamp` / `payload` / `level` / `trace_id`。
- **stdout**：仅模型与用户对话内容（F08 main_loop 的 `AIMessage.content` 写入）；**不得混入日志**。
- **可选磁盘文件**：`~/.local/share/langagent/logs/<run-id>.jsonl`（默认关闭，由 F09 启用）。

> **review.md S-6 修复对齐 `workflow.md#langagent-run`**：日志全部走 stderr；stdout 仅对话。避免对话内容与日志交错输出无法区分。

## 五、关键约束

1. **`la.` 前缀刚性**：tag 白名单仅允许 `la.` 开头；绝不出现 `langsmith.*` / `langfuse.*`（宪法第 III 条 + 第 XIII 条）。
2. **不写磁盘 by default**：纯 stderr 流（文本 + JSONL）+ stdout 流（仅对话）；磁盘文件由 F09 启用（避免日志 IO 错误阻塞主循环）；**review.md S-6 修复**：日志不再写 stdout。
3. **不阻塞主流程**：`emit()` 必须是 fire-and-forget；任何 IO 异常只能 stderr 输出一次，不能抛异常到 caller。
4. **脱敏刚性**：payload 含 `api_key` / `password` / `secret` / `token` 字段名 → 输出前替换为 `***`（硬编码字段名清单）。
5. **白名单登记**：≥45 个 tag（**review.md v0.3.0 s-1 / s-2 修复后**）必须显式登记到 `ALLOWED_TAGS` 集合；未登记的 tag 在 `emit()` 时抛异常，避免拼写错误静默丢日志。
6. **依赖方向（review.md v0.5.0 评审 v0.1.0 §二.A.3 方案 A 修复明确）**：cross_cutting 不依赖 runtime / cli / **protocol 模块的具体实现**；EventBusProtocol 接口定义位于 `cross_cutting/logger.py` 内（与 logger 接口同模块，**v0.5.0 起合并**），F03 的 `protocol_event_bus` 实现该接口，运行时注入（**依赖反转**）。review.md v0.4.0 m-2 修复时的独立 `cross_cutting/event_bus_protocol.py` 文件被合并掉。
7. **被动接口约束**（**review.md v2.1.0 P2-3 修复新增**）：logger 与 EventBusProtocol 都是被动接口——`emit()` / `publish()` / `subscribe()` 调用方主动 push，F02 不反向依赖任何调用方；F02 metrics_collector 通过 `EventBusProtocol.subscribe()` 订阅事件是被动消费者（订阅者只读不写，不形成反向依赖；依赖矩阵中 `cross_cutting_metrics_collector → protocol_event_bus` 是 cross_cutting 内部允许边）。
8. **TDD 刚性**：先 Red 后 Green 再 Refactor；metrics 测试可 mock `EventBusProtocol` 接口（F02 自有），F03 实现该协议。
9. **不写绝对路径 / 内网 IP**（宪法第 XIII 条 6 款）。
10. **第 XV 条对齐清单**：与宪法第 III 条（LangSmith 剥离）/ 第 IX 条（Tracing + Monitoring）/ 第 XII 条（可观测契约）/ 第 XIII 条（Hard No）逐项对齐。
