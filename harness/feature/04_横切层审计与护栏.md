## 一、Feature 概述

实现 cross_cutting 层的安全相关 2 个模块：
- **`cross_cutting_audit_recorder`**：当 guardrail 拦截 / PII 泄露 / 越权 tool 调用 / prompt injection 时，append-only 写入 `AuditEntry`。
- **`cross_cutting_guardrail_middleware`**：根据三级护栏模式（all / smart / strict）和工具级 `requires_approval` 标注决定是否触发 LangGraph `interrupt()`；实现 LangChain `AgentMiddleware` 协议，注入到 LangGraph 图。

这是 LangAgent 安全护栏（Guardrails）的唯一实现入口。

### 3.2 Schema

- `AuditEntry`（9 字段：`entry_id` / `audited_at` / `severity` / `category` / `actor` / `action` / `target` / `outcome` / `evidence`）。
- **顶层 schema（F04 拥有，详见 `module_schemas.md#schema-guardrail-policy`）**：
  - `GuardrailMode`：Literal["all", "smart", "strict"]（三级护栏模式）
  - `GuardrailPolicy`（5 字段：`enabled` / `mode` / `redact_pii` / `allow_internal_endpoints` / `internal_endpoint_patterns`）
  - `GuardrailDecision`（5 字段：`allow` / `interrupt` / `redact` / `reason` / `is_internal_endpoint`）
- **三级护栏模式说明**：
  - `all`：所有工具调用均需人工审批（interrupt）
  - `smart`：根据工具级 `requires_approval` 标注决策（默认模式）
  - `strict`：禁止所有工具调用（deny-all）
- **F07 注入机制**：RuntimeConfig 新增 `guardrail_policy: GuardrailPolicy | None = None` 字段；F07 config_resolve 读 env `LANGAGENT_GUARDRAIL_MODE`（all / smart / strict）+ `LANGAGENT_GUARDRAIL_ALLOW_INTERNAL_ENDPOINTS`（bool）+ `LANGAGENT_INTERNAL_ENDPOINTS`（逗号分隔 glob / CIDR 列表）→ 解析为 GuardrailPolicy 实例 → `config = config.with_guardrail_policy(policy)` 重建 RuntimeConfig（frozen 实例）。F04 evaluate() 直接读 `config.guardrail_policy` 而非自读 env。

### 3.3 审计写入策略

- **append-only**：`write()` 永不修改历史条目；写失败抛 `AuditFlushError`，退出码 4（I/O 错误）。
- **写入路径**：`~/.local/share/langagent/audit.jsonl`（一行一条 JSON）。
- **脱敏**：`evidence` 字段中的 `api_key` / `password` / `token` / 邮件地址 / 手机号在写盘前替换为 `***`。
- **查询接口**：`query(category, since)` 返回 list[AuditEntry]，仅按 `category` 精确匹配 + `audited_at >= since` 过滤。

### 3.4 护栏三级模式决策规则

F04 guardrail_middleware 根据 `GuardrailPolicy.mode`（all / smart / strict）和工具级 `ToolSpec.requires_approval` 标注决定是否触发 interrupt：

| `GuardrailPolicy.mode` | `ToolSpec.requires_approval` | 决策结果 | 说明 |
|---|---|---|---|
| `strict` | 任意 | **interrupt + deny**（`allow=False, interrupt=True`） | 禁止所有工具调用（deny-all 模式） |
| `all` | 任意 | **interrupt**（`allow=False, interrupt=True`） | 所有工具调用均需人工审批 |
| `smart` | `True` | **interrupt**（`allow=False, interrupt=True`） | 仅审批标注 `requires_approval=True` 的工具 |
| `smart` | `False` | **allow**（`allow=True, interrupt=False`） | 放行未标注 `requires_approval` 的工具 |

**默认模式**：`smart`（符合宪法第 X 条 2 款"工具权限最小化"——开发者显式标注 `requires_approval=True` 的工具触发 HITL 审批）。

**evaluate() 决策算法**（伪代码）：

```python
def evaluate(tool_spec: ToolSpec, config: RuntimeConfig) -> GuardrailDecision:
    policy = config.guardrail_policy or GuardrailPolicy(enabled=True, mode="smart")
    
    if not policy.enabled:
        return GuardrailDecision(allow=True, interrupt=False, reason="guardrail disabled")
    
    # strict 模式：禁止所有工具
    if policy.mode == "strict":
        return GuardrailDecision(
            allow=False, interrupt=True, redact=False,
            reason="strict mode: deny all tools"
        )
    
    # all 模式：所有工具均需审批
    if policy.mode == "all":
        return GuardrailDecision(
            allow=False, interrupt=True, redact=False,
            reason="all mode: all tools require approval"
        )
    
    # smart 模式：根据工具级 requires_approval 决策
    if tool_spec.requires_approval:
        return GuardrailDecision(
            allow=False, interrupt=True, redact=False,
            reason=f"tool {tool_spec.tool_id} requires_approval=True"
        )
    
    # smart 模式 + requires_approval=False：放行
    return GuardrailDecision(
        allow=True, interrupt=False, redact=False,
        reason=f"tool {tool_spec.tool_id} approved in smart mode"
    )
```

**审计策略**：
- `strict` / `all` 模式：所有拦截写 `AuditEntry(category=unauthorized_tool, severity=warn)`
- `smart` 模式 + `requires_approval=True`：写 `AuditEntry(category=unauthorized_tool, severity=info)`
- `smart` 模式 + `requires_approval=False`：不写审计（放行工具无需审计）

### 3.4a 内网 endpoint 决策细则（扩展规则，与三级模式正交）

内网 endpoint 检测是对三级模式的补充规则，用于支持宪法第 X 条 1 款"不外发数据"与第 IV 条 4 款"本地模型必须可作为默认"。本地 OpenAI Compatible（vLLM Qwen3.8-27B）走 `ChatOpenAI` 协议 + `base_url` 实际是网络调用（即便内网），需要在护栏决策中区分内网 vs 公网 endpoint。

**与三级模式的关系**：
- `strict` 模式：无论内网 / 公网，全部 deny
- `all` 模式：无论内网 / 公网，全部 interrupt
- `smart` 模式：
  - 工具 `requires_approval=True` → interrupt（无论 endpoint）
  - 工具 `requires_approval=False` + 内网 endpoint → allow（`is_internal_endpoint=True`）
  - 工具 `requires_approval=False` + 公网 endpoint → interrupt（提示用户该工具可能外发数据）

**`is_internal()` 辅助函数**（在 `evaluate()` 中调用）：

```python
def is_internal(endpoint: str, patterns: list[str]) -> bool:
    """检查 endpoint 是否命中内网 pattern。endpoint 形如 'http://10.0.0.5:8000/v1'。"""
    from urllib.parse import urlparse
    import ipaddress
    import fnmatch
    
    parsed = urlparse(endpoint)
    host = parsed.hostname or ""
    
    for pat in patterns:
        # 支持 IP CIDR / hostname glob
        try:
            ip = ipaddress.ip_address(host)
            if ip in ipaddress.ip_network(pat, strict=False):
                return True
        except ValueError:
            # hostname glob match
            if fnmatch.fnmatch(host, pat):
                return True
    return False
```

**扩展后的 evaluate() 伪代码**（smart 模式下检测 endpoint）：

```python
def evaluate(tool_spec: ToolSpec, config: RuntimeConfig) -> GuardrailDecision:
    policy = config.guardrail_policy or GuardrailPolicy(enabled=True, mode="smart")
    
    if not policy.enabled:
        return GuardrailDecision(allow=True, interrupt=False, reason="guardrail disabled")
    
    # strict / all 模式逻辑不变（见 §3.4）
    if policy.mode == "strict":
        return GuardrailDecision(allow=False, interrupt=True, reason="strict mode")
    if policy.mode == "all":
        return GuardrailDecision(allow=False, interrupt=True, reason="all mode")
    
    # smart 模式：优先检查 requires_approval
    if tool_spec.requires_approval:
        return GuardrailDecision(allow=False, interrupt=True, reason="requires_approval=True")
    
    # smart 模式 + requires_approval=False：检查是否为网络调用工具
    # （注：实际实现中需通过 tool 元数据判断是否涉及网络；此处简化为检查 config.model_base_url）
    endpoint = config.model_base_url
    if endpoint and policy.allow_internal_endpoints:
        if is_internal(endpoint, policy.internal_endpoint_patterns):
            return GuardrailDecision(
                allow=True, interrupt=False, is_internal_endpoint=True,
                reason=f"internal endpoint {endpoint}"
            )
        else:
            # 公网 endpoint：smart 模式下提示审批
            return GuardrailDecision(
                allow=False, interrupt=True, is_internal_endpoint=False,
                reason=f"public endpoint {endpoint} requires approval"
            )
    
    # 默认 allow（smart 模式 + requires_approval=False + 无网络调用）
    return GuardrailDecision(allow=True, interrupt=False, reason="smart mode allow")
```

### 3.5 中间件接入点（LangChain `AgentMiddleware`）

F04 guardrail_middleware 实现 LangChain `AgentMiddleware` 协议（通过 `primitives_langchain_types` re-export），在以下 3 个 hook points 接入：

- `before_tools`：检查即将执行的 tool 调用，根据三级模式 + requires_approval 标注决定是否触发 interrupt。
- `after_tools`：检查 tool 返回值是否含 PII，按 `GuardrailPolicy.redact_pii` 配置脱敏。
- `wrap_model_call`：检查模型输入是否含 prompt injection 模式（启发式正则）；标记 untrusted content。

```python
# F04 中间件实现示例（AgentMiddleware 从 primitives 层 re-export）
from langagent.primitives.langchain_types import AgentMiddleware
from langagent.cross_cutting.types import GuardrailPolicy, GuardrailDecision

def build_middleware(policy: GuardrailPolicy) -> AgentMiddleware:
    """构造 guardrail middleware 实例；由 F10 state_graph_builder 调用。"""
    class GuardrailMiddleware(AgentMiddleware):
        def before_tools(self, tool_calls, config):
            for call in tool_calls:
                tool_spec = get_tool_spec(call.tool_id)
                decision = evaluate(tool_spec, config)
                if decision.interrupt:
                    # 触发 LangGraph interrupt + 写审计
                    raise InterruptException(reason=decision.reason)
        
        def after_tools(self, tool_results, config):
            if policy.redact_pii:
                return redact_pii_in_results(tool_results)
            return tool_results
        
        def wrap_model_call(self, messages, config):
            # prompt injection 检测（启发式）
            detect_prompt_injection(messages)
            return messages
    
    return GuardrailMiddleware()
```

## 五、关键约束

1. **append-only 刚性**：审计文件不得 truncate / overwrite；写入失败必须抛错而非静默丢。
2. **默认 smart 模式**：默认护栏模式为 `smart`，仅拦截标注 `requires_approval=True` 的工具；用户可通过 env `LANGAGENT_GUARDRAIL_MODE` 切换为 `all`（全部审批）或 `strict`（禁止所有工具）。
3. **PII / 密钥脱敏**：api_key / password / token / email / phone 在写盘前替换；测试必须验证。
4. **prompt injection 防御**：来自 tool 返回值 / 检索片段的文本不直接拼进 system prompt；middleware 标记 untrusted content（宪法第 X 条 3 款）。
5. **不外发数据**：guardrail 不调用任何外部服务（如云端 PII 检测）；检测必须本地启发式（宪法第 X 条 1 款）。
6. **依赖 LangChain `AgentMiddleware` 协议**：F04 是 LangAgent 与 LangChain middleware 的接触面；类型注解必须严格匹配。
7. **依赖方向**：cross_cutting 不依赖 runtime / cli / protocol_skill_loader / protocol_tool_registry；仅 primitives（类型注解）+ cross_cutting_logger + protocol_event_bus + cross_cutting_audit_recorder。
8. **TDD 刚性**：先 Red 后 Green 再 Refactor；mock 真实 LangGraph 中间件链（让协议跑通而非跳到图）。
9. **第 XV 条对齐清单**：与宪法第 VII 条（middleware 接入方式）/ 第 IX 条（Guardrails 子能力）/ 第 X 条（安全与隐私）/ 第 XIII 条逐项对齐。
